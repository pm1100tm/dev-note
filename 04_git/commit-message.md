# 커밋 메시지 템플릿

커밋 메시지는 코드 변경의 의도와 범위를 빠르게 파악하기 위한 기록입니다.
제목에는 무엇을 바꿨는지, 본문에는 왜 바꿨는지와 영향 범위를 남깁니다.

## 기본 구조

```text
<type>(<scope>): <제목>

<변경 이유와 주요 내용>

<참조 이슈 또는 호환성 안내>
```

- `type`은 변경 성격입니다. 팀 규칙이 있다면 그 규칙을 우선합니다.
- `scope`은 영향을 받는 기능이나 모듈입니다. 구분할 필요가 없으면
  생략할 수 있습니다.
- 제목은 변경 결과를 한 문장으로 요약합니다.
- 본문과 푸터는 변경이 단순할 때 생략할 수 있습니다.

## 템플릿 설정

```shell
touch ~/.gitmessage

# 설정
git config --global commit.template ~/.gitmessage
git config --local commit.template .gitmessage

# 해제
git config --global --unset commit.template
git config --local --unset commit.template

# 확인
git config --global --get commit.template
git config --get commit.template
```

> --local 로 설정 후 해제/확인 명령어는 --local 옵션을 붙이지 우선순위에 의해서 동작한다.

`~/.gitmessage`에 다음과 같은 안내 문구를 작성할 수 있습니다.

```text
# <type>(<scope>): <제목>
#
# 변경 이유와 주요 내용을 작성합니다.
# Refs: #<issue-number>
```

`git commit`을 실행하면 편집기에 템플릿이 열립니다. `#`으로 시작하는 줄은
커밋 메시지에 포함되지 않습니다.

## 예시

```text
feat(auth): 로그인 실패 횟수 제한 추가

- 반복 로그인 실패 시 계정 잠금 정책을 적용합니다.
- 관리자 해제 API와 감사 로그를 추가합니다.

Refs: #123
```

## 권장 규칙

- 제목은 보통 50자 안팎으로 쓰고 마침표를 생략합니다.
- 제목과 본문 사이는 빈 줄로 구분합니다.
- 제목은 명령형보다 변경 결과가 드러나도록 작성합니다.
  - `로그인 실패 횟수 제한 추가`
  - `주문 조회 API의 시간 초과 처리 개선`
- 본문에는 구현 세부 사항보다 변경 이유, 사용자·다른 서비스에 미치는 영향,
  주의할 점을 우선 기록합니다.
- 하나의 커밋에는 하나의 논리적 변경을 담습니다. 기능 추가와 무관한 포맷 변경은
  분리합니다.

## 자주 쓰는 type

| Type       | 사용 예시                  |
| ---------- | -------------------------- |
| `feat`     | 사용자 기능 추가           |
| `fix`      | 결함 수정                  |
| `docs`     | 문서 변경                  |
| `refactor` | 동작 변경 없는 구조 개선   |
| `test`     | 테스트 추가·수정           |
| `build`    | 빌드 도구·의존성 설정 변경 |
| `ci`       | CI 설정 변경               |
| `chore`    | 그 밖의 유지보수 작업      |

type 이름 자체보다 팀 전체가 같은 의미로 사용하는 것이 중요합니다.

## .gitmessage 샘플

아래 내용을 `~/.gitmessage`에 저장하면 대부분의 프로젝트에서 사용할 수 있습니다.
대괄호로 표시한 항목은 필요한 경우에만 작성합니다.

```shell
# <type>(<scope>): <제목>
#
# type: feat, fix, docs, refactor, test, build, ci, chore
# scope: 변경한 기능 또는 모듈 이름. 필요 없으면 생략
# 제목: 무엇을 바꿨는지 50자 안팎으로 작성하고 마침표 생략
#
# 변경 이유와 주요 내용을 작성합니다.
# - 사용자, API, 데이터, 배포에 미치는 영향이 있으면 함께 작성합니다.
# - 호환성이 깨지거나 수동 조치가 필요하면 반드시 작성합니다.
#
# [Refs: #이슈번호]
# [BREAKING CHANGE: 호환되지 않는 변경 내용]
```

이 템플릿의 모든 줄은 주석이므로, 작성할 때 안내 문구를 지우지 않아도 최종 커밋
메시지에는 포함되지 않습니다. 단, Git 설정 `core.commentChar`를 변경했다면 주석
문자도 그 설정에 맞춰 바꿉니다.
