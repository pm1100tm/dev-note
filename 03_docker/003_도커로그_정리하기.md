# Docker 로그 정리

기본 `json-file` 로깅 드라이버는 컨테이너의 stdout과 stderr를 호스트 디스크에 저장한다.
로그 회전 정책이 없으면 `/var/lib/docker`가 가득 차 이미지 pull, 컨테이너 시작, OS 동작에
문제가 생길 수 있다.

## 상태 확인

```shell
docker info --format '{{.LoggingDriver}}'
docker logs --tail 100 <container-name>
sudo du -h /var/lib/docker/containers/*/*-json.log | sort -h
df -h /var/lib/docker
```

`/var/lib/docker`는 Linux 기본 설치 경로이며, Docker Desktop과 rootless Docker에서는 다를 수
있다. 실제 위치와 로깅 드라이버를 먼저 확인한다.

## 즉시 대응

```shell
docker ps -a --no-trunc
sudo truncate -s 0 /var/lib/docker/containers/<container-id>/<container-id>-json.log
```

- `truncate`는 파일 핸들을 유지한 채 내용을 비운다. `rm`으로 실행 중인 로그 파일을 지우지 않는다.
- 이 작업은 로그를 복구할 수 없게 한다. 장애 분석에 필요한 로그는 먼저 외부에 보관한다.
- 전체 경로 와일드카드를 대상으로 일괄 삭제하지 말고, 대상 컨테이너와 파일을 확인한다.

## 재발 방지

```yaml
services:
  app:
    image: example/app:1.0
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "5"
```

변경 후 새로 생성되는 컨테이너에 정책이 적용된다. 전역 기본값은 `/etc/docker/daemon.json`에
설정할 수 있으며 Docker 데몬 재시작의 영향 범위를 사전에 검토해야 한다.

중요 로그는 CloudWatch, Loki, Elasticsearch 같은 중앙 수집 시스템으로 보내고, 디스크 사용량
알림도 함께 둔다. `docker system prune --volumes`는 로그 관리의 대안이 아니며 데이터 손실을
일으킬 수 있다.
