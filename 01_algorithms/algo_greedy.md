# 탐욕 알고리즘(Greedy Algorithm)

탐욕 알고리즘은 매 단계에서 현재 기준으로 가장 좋아 보이는 선택을 하고, 이전 선택을 되돌리지 않는 방식입니다. 구현이 단순하고
빠른 경우가 많지만, **지역 최적 선택이 전체 최적해로 이어진다는 근거**가 있어야 정확한 답을 보장합니다.

## 적용 조건

탐욕 알고리즘으로 최적해를 구하려면 보통 다음 성질을 확인해야 합니다.

- **탐욕 선택 속성(Greedy Choice Property)**: 현재의 최선 선택을 포함하는 최적해가 존재합니다.
- **최적 부분 구조(Optimal Substructure)**: 전체 문제의 최적해가 부분 문제의 최적해로 구성됩니다.

최적 부분 구조는 동적 계획법에도 나타납니다. 차이는 동적 계획법이 여러 선택을 저장하고 비교하는 반면, 탐욕 알고리즘은 하나의
선택을 확정하고 진행한다는 점입니다.

## 정답을 증명하는 방법

탐욕 문제는 구현보다 정당성 증명이 중요합니다. 자주 사용하는 증명 방식은 다음과 같습니다.

- **교환 논증**: 어떤 최적해의 선택을 탐욕적 선택으로 바꾸어도 결과가 나빠지지 않음을 보입니다.
- **귀류법**: 탐욕적 선택을 포함하지 않는 더 좋은 해가 있다고 가정한 뒤 모순을 찾습니다.
- **귀납법**: 첫 선택이 안전함을 보이고, 남은 부분 문제에서도 같은 성질이 유지됨을 보입니다.

## 예제: 동전 개수 최소화

동전 단위가 `[1, 5, 10, 25]`이고 금액이 `63`이라면 큰 동전부터 선택해 `25 + 25 + 10 + 1 + 1 + 1`, 총 6개로
만들 수 있습니다.

```python
def min_coin_count(denominations: list[int], amount: int) -> int:
    if amount < 0 or any(coin <= 0 for coin in denominations):
        raise ValueError("금액은 음수가 아니고 동전 단위는 양수여야 합니다.")

    remaining = amount
    count = 0

    for coin in sorted(set(denominations), reverse=True):
        quotient, remaining = divmod(remaining, coin)
        count += quotient

    return count if remaining == 0 else -1


assert min_coin_count([1, 5, 10, 25], 63) == 6
assert min_coin_count([2, 5, 10, 25], 63) == -1
```

### 그리디가 실패하는 반례

큰 동전부터 사용하는 전략이 모든 동전 체계에서 최적은 아닙니다. 동전이 `[1, 3, 4]`, 금액이 `6`인 경우 그리디는
`4 + 1 + 1`로 3개를 선택하지만 최적해는 `3 + 3`의 2개입니다.

따라서 위 구현은 임의의 동전 체계에 대한 일반 해법이 아닙니다. 동전 체계의 성질을 증명할 수 없다면 동적 계획법이나
최단 경로 방식 등을 고려해야 합니다.

## 탐욕 알고리즘과 근사 알고리즘

탐욕 알고리즘이 항상 근사값만 구하는 것은 아닙니다. 활동 선택, 최소 신장 트리, 허프만 코딩처럼 조건을 만족하면
**정확한 최적해**를 구합니다. 한편 NP-hard 문제 등에서 최적해를 효율적으로 구하기 어려울 때 탐욕 전략을 근사 알고리즘으로
활용하기도 합니다. 이 경우에는 가능하면 근사 비율처럼 해의 품질을 설명할 수 있어야 합니다.

## 문제 풀이 체크리스트

- 1. 매 단계에서 무엇을 기준으로 선택할지 정의합니다.
- 2. 선택 후 남은 문제가 같은 형태의 부분 문제인지 확인합니다.
- 3. 교환 논증이나 귀납법으로 선택의 안전성을 증명합니다.
- 4. 작은 입력을 완전 탐색해 그리디 결과와 비교하고 반례를 찾습니다.
- 5. 증명할 수 없다면 동적 계획법, 완전 탐색, 그래프 알고리즘을 검토합니다.
