# iOS 앱 여러가지 다운로드 방법

## ✏️ 결론

iOS 앱 파일인 `.ipa`는 일반적인 방식으로 웹에서 직접 다운로드하여 설치할 수 없습니다.

Android에서는 APK 파일을 웹에서 다운로드한 뒤 사용자가 설치를 허용하면 설치할 수 있습니다.
하지만 iOS에서는 보안 정책상 임의의 `.ipa` 파일을 Safari나 파일 앱에서 바로 실행하거나 설치하는
방식이 허용되지 않습니다.

iOS 앱을 설치하려면 Apple이 허용한 배포 방식과 유효한 코드 서명, 프로비저닝 조건을 만족해야 합니다.

## 직접 설치가 불가능한 이유

iOS 앱은 반드시 Apple 개발자 인증서로 서명되어 있어야 합니다.

또한, 앱을 실행할 기기가 해당 앱의 프로비저닝 조건에 포함되어 있어야 합니다.

즉, 단순히 `.ipa` 파일만 가지고 있다고 해서 설치할 수 있는 것이 아닙니다. 다음 조건이 필요합니다.

- 유효한 Apple 개발자 인증서
- 올바른 코드 서명
- 배포 방식에 맞는 프로비저닝 프로파일
- 설치 대상 기기의 권한 또는 등록 상태
- iOS가 신뢰하는 설치 경로

Safari에서 `.ipa` 파일을 다운로드하거나 파일 앱에서 `.ipa`를 열어도 일반적인 앱 설치는 진행되지 않습니다.

---

## 예외적으로 가능한 설치 방법

### 1️⃣ App Store 배포

가장 일반적인 공식 배포 방식입니다.

앱을 App Store Connect에 업로드하고 Apple 심사를 통과한 뒤 App Store를 통해 배포합니다.

특징은 다음과 같습니다.

- 일반 사용자 대상 배포가 가능합니다.
- Apple 심사가 필요합니다.
- 앱 업데이트, 결제, 배포 관리는 App Store를 통해 이루어집니다.
- 임의의 `.ipa` 파일을 직접 설치하는 방식은 아닙니다.

### 2️⃣ TestFlight 배포

개발 중이거나 베타 테스트용 앱을 배포할 때 사용하는 Apple의 공식 베타 배포 방식입니다.

개발자가 App Store Connect에 앱을 업로드하고, 테스터는 TestFlight 앱을 통해 설치합니다.

특징은 다음과 같습니다.

- 베타 테스트 목적의 배포 방식입니다.
- 외부 테스터 배포에는 Apple 심사가 필요합니다.
- 설치는 TestFlight를 통해 진행합니다.
- `.ipa` 파일을 사용자가 직접 다운로드해서 설치하는 방식은 아닙니다.
- 테스트 기간 제한이 있습니다.

### 3️⃣ Ad Hoc 배포

특정 기기만 대상으로 `.ipa`를 배포할 수 있는 방식입니다.

개발자가 설치 대상 iPhone 또는 iPad의 UDID를 Apple Developer 계정에 등록하고, 해당 기기들이
포함된 Ad Hoc 프로비저닝 프로파일로 앱을 빌드해야 합니다.

> UDID(Unique Device Identifier)
>
> 애플 기기마다 부여된 40자리 길이의 고유한 기기 식별자

특징은 다음과 같습니다.

- 등록된 기기에서만 설치할 수 있습니다.
- 기기 UDID 사전 등록이 필요합니다.
- Apple Developer Program이 필요합니다.
- 제한된 테스트 또는 내부 검증 용도로 사용합니다.
- 웹 링크를 통한 설치가 가능할 수 있지만, 반드시 manifest plist와 올바른 서명, 프로비저닝이 필요합니다.

웹 설치 예시는 보통 다음 형태를 사용합니다.

```html
<a
  href="itms-services://?action=download-manifest&url=https://example.com/app/manifest.plist"
>
  Install App
</a>
```

다만 이 방식은 아무 `.ipa`나 설치하는 기능이 아닙니다. Ad Hoc으로 서명된 `.ipa`,
HTTPS로 접근 가능한 manifest plist, 등록된 기기 조건이 모두 맞아야 합니다.

### Enterprise 배포

Apple Developer Enterprise Program을 통해 조직 내부 직원에게 앱을 배포하는 방식입니다.

특징은 다음과 같습니다.

- 조직 내부 사용자를 위한 배포 방식입니다.
- App Store 심사 없이 내부 배포가 가능합니다.
- 일반 대중 배포는 금지됩니다.
- **Enterprise 인증서로 서명해야 합니다.**
- **인증서 신뢰 설정이 필요할 수 있습니다.**
- **정책 위반 시 인증서가 폐기될 수 있습니다.**

웹 기반 설치는 Ad Hoc과 유사하게 `itms-services` 링크를 사용할 수 있습니다.

하지만 이 방식은 회사 내부 배포용입니다. 일반 사용자에게 앱을 배포하기 위한 우회 수단으로 사용하면
Apple 정책 위반입니다.

---

### MDM 배포

기업이나 기관에서 Mobile Device Management 시스템을 통해 앱을 배포하는 방식입니다.

특징은 다음과 같습니다.

- 관리 대상 기기에 앱을 설치할 수 있습니다.
- 내부 앱 배포에 사용합니다.
- Enterprise 또는 Apple Business Manager와 함께 사용하는 경우가 많습니다.
- 사용자가 웹에서 직접 `.ipa`를 다운로드해 설치하는 방식과 다릅니다.
- 조직 관리 환경이 필요합니다.

### Xcode를 통한 직접 설치

개발자가 Mac에서 Xcode를 사용해 연결된 iPhone에 앱을 직접 빌드 및 설치할 수 있습니다.

특징은 다음과 같습니다.

- 개발 및 디버깅 목적의 설치 방식입니다.
- 소스 코드 또는 Xcode 프로젝트가 필요합니다.
- 개발자 계정이 필요합니다.
- 무료 Apple ID도 제한적으로 가능하지만 제약이 많습니다.
- `.ipa` 파일을 웹에서 받아 설치하는 일반 사용자 방식은 아닙니다.

### Apple Configurator를 통한 설치

Mac의 Apple Configurator를 사용해 특정 `.ipa`를 관리 대상 기기에 설치할 수 있는 경우가 있습니다.

특징은 다음과 같습니다.

- 주로 기업, 교육기관, 관리 기기 환경에서 사용합니다.
- 올바르게 서명된 앱이 필요합니다.
- 일반적인 웹 다운로드 설치 방식은 아닙니다.

## 웹에서 ipa 설치가 가능한 것처럼 보이는 경우

일부 문서나 내부 배포 시스템에서는 웹 페이지에서 설치 버튼을 누르면 앱이 설치되는 것처럼 보일 수 있습니다.

하지만 실제로는 다음 조건을 만족하는 특수한 배포 방식입니다.

- `.ipa`가 올바른 인증서로 서명되어 있습니다.
- 배포 방식에 맞는 프로비저닝 프로파일이 포함되어 있습니다.
- 설치 대상 기기가 허용되어 있습니다.
- HTTPS로 manifest plist를 제공합니다.
- `itms-services` 스킴을 통해 iOS 설치 프로세스를 호출합니다.

즉, 단순히 `.ipa` 파일을 웹 서버에 올려놓는다고 설치되는 것이 아닙니다.

## Android APK 설치와의 차이

Android는 사용자가 알 수 없는 앱 설치 권한을 허용하면 APK 파일을 직접 설치할 수 있습니다.

반면 iOS는 일반 사용자에게 임의 앱 설치 권한을 제공하지 않습니다.

| 항목                           | Android                                   | iOS                  |
| ------------------------------ | ----------------------------------------- | -------------------- |
| 파일 형식                      | APK, AAB                                  | IPA                  |
| 웹 다운로드 후 직접 설치       | 가능                                      | 일반적으로 불가능    |
| 사용자 설정으로 허용 가능 여부 | 가능                                      | 불가능               |
| 공식 외부 테스트 배포          | 내부 테스트, Firebase App Distribution 등 | TestFlight           |
| 특정 기기 대상 배포            | 가능                                      | Ad Hoc 필요          |
| 기업 내부 배포                 | 가능                                      | Enterprise, MDM 필요 |
| 코드 서명 강제                 | 있음                                      | 매우 강함            |

---

## 정리

iOS에서 `.ipa` 파일을 웹에서 다운로드하여 바로 설치하는 일반적인 방법은 없습니다.

가능한 예외는 다음과 같습니다.

- App Store
- TestFlight
- Ad Hoc 배포
- Enterprise 배포
- MDM 배포
- Xcode 직접 설치
- Apple Configurator 사용

이 중 웹 링크를 통한 설치처럼 보이는 방식은 주로 Ad Hoc 또는 Enterprise
배포에서 `itms-services`와 manifest plist를 사용하는 방식입니다.

하지만 이 경우에도 `.ipa` 파일이 적절하게 서명되어 있어야 하며, 설치 대상 기기와 배포 정책 조건을
만족해야 합니다.

따라서 "웹에서 ipa 파일을 받아서 설치한다"는 표현은 정확하지 않습니다.

정확히는 "Apple이 허용한 배포 방식으로 서명된 ipa를, 허용된 기기에 설치한다"라고 이해해야 합니다.
