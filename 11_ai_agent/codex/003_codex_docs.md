# Codex 지침 만들기

> 확인일: 2026-09-10. Codex 공식 문서를 기준으로 정리했다. 파일 탐색 설명은 로컬 Codex CLI 기준이며,
> 앱·플러그인이 제공하는 스킬은 설치 방식과 표시 위치가 다를 수 있다.

## 어떤 파일을 만들면 되는가?

Codex에서는 **프로젝트의 공통 작업 규칙은 `AGENTS.md`, 특정 작업의 재사용 절차는 `SKILL.md`**로 작성한다.

| 구분               | 적을 내용                                               |
| ------------------ | ------------------------------------------------------- |
| `AGENTS.md`        | 작업 전에 알아야 할 프로젝트 규칙, 문서 형식, 검증 방법 |
| `SKILL.md`         | 특정 작업의 사용 조건, 수행 절차, 결과물과 완료 기준    |
| 일반 Markdown 문서 | 상세 설명, 설계 배경, 참고 자료                         |
| 이번 대화의 요청   | 지금 수정할 파일, 이번 작업의 목표와 예외               |

Codex용 기본 파일명은 대소문자를 포함해 `AGENTS.md`, `SKILL.md`로 맞춘다.

- [공식 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
- [공식 스킬 안내](https://learn.chatgpt.com/docs/build-skills)

## 어떤 원리로 작동하는가?

지침을 만드는 것은 모델을 재학습시키는 작업이 아니다. 작업에 필요한 규칙과 절차를 모델이 읽을 문맥에 제공하는 방식이다.

```shell
사용자 요청
    ↓
적용할 AGENTS.md의 공통 규칙
    ↓
요청과 관련된 스킬 선택 → SKILL.md 읽기
    ↓
필요한 참고 문서 읽기 → 파일 수정·검증 → 결과 보고
```

이 그림은 개념적인 흐름이다. 모든 파일을 매번 전부 읽는다는 뜻은 아니다.

- `AGENTS.md`는 시작 시 탐색한 지침을 합쳐 적용한다.
- 스킬은 이름과 설명을 먼저 제공하고, 선택되면 상세 본문을 읽는 **점진적 로딩** 방식을 사용한다.
- 따라서 공통 규칙을 짧게 유지하고, 긴 작업 절차를 스킬로 분리하면 필요한 내용을 찾기 쉽다.

<br>

- [지침 탐색 원리](https://learn.chatgpt.com/docs/agent-configuration/agents-md),
- [스킬 로딩 원리](https://learn.chatgpt.com/docs/build-skills)

지침은 행동을 유도하지만 프로그램의 강제 검사와 같지는 않다. 파일 형식이나 테스트 통과처럼 반드시 보장해야 하는 조건은
linter, 테스트, CI로도 검증한다. 또한 지침 문구만으로 실행 환경의 파일·네트워크 권한을 부여할 수는 없다.

## Step 1. 반복해서 요청하는 내용을 분류하기

처음부터 큰 문서를 만들기보다, 실제로 반복해서 설명했던 요구를 적는다. 다음은 이 개발 노트 저장소에 맞춘 작성 예시다.

| 반복하는 요청                                  | 넣을 위치                      |
| ---------------------------------------------- | ------------------------------ |
| 설명은 한국어로 작성해 줘                      | 개인 또는 프로젝트 `AGENTS.md` |
| Markdown 목록은 숫자 대신 `-`를 사용해 줘      | 프로젝트 `AGENTS.md`           |
| 기존 작성 내용을 먼저 확인하고 수정해 줘       | 프로젝트 `AGENTS.md`           |
| 설치 가이드는 준비부터 실행 확인까지 작성해 줘 | 설치 가이드 작성 스킬          |
| 새 문서를 만들 때 목차 등록까지 확인해 줘      | 문서 추가 스킬                 |
| 이번 문서에서는 Docker 설치를 생략해 줘        | 이번 대화의 요청               |

개인 취향은 개인 지침, 팀이 공유할 규칙은 저장소 지침에 둔다. 일회성 요구를 공통 지침에 계속 쌓지 않는다.

## Step 2. 프로젝트 루트에 AGENTS.md 작성하기

예를 들어 다음 위치에 파일을 만든다.

```shell
dev-note/
├── AGENTS.md
├── README.md
├── SUMMARY.md
└── 11_ai_agent/
```

아래는 복사한 뒤 프로젝트에 맞게 조정할 수 있는 예시다. YAML 머리말 없이 일반 Markdown으로 작성한다.

```markdown
# 개발 노트 작성 규칙

## 프로젝트 목적

- 개발 지식과 문제 해결 방법을 한국어 Markdown 문서로 정리한다.
- 문서의 독자는 해당 작업을 처음 따라 하는 개발자다.

## 수정 전 확인

- 대상 파일의 기존 내용과 인접 문서의 형식을 먼저 확인한다.
- 사용자가 이미 작성한 내용은 요청 범위에 맞게 보존한다.
- 실행 명령이나 파일 경로는 저장소에서 확인한 값을 사용한다.

## 문서 형식

- 목록은 숫자 목록 대신 `-` 불릿으로 작성한다.
- 제목과 목록 앞뒤에 빈 줄을 둔다.
- 명령은 언어를 지정한 코드 블록에 작성한다.
- 예시 값과 실제 환경에서 확인한 값을 구분한다.
- 새로 시작하는 안내에서는 파일이 이미 있다고 가정하지 않는다.

## 검증

- 수정한 문서의 상대 링크가 실제 파일을 가리키는지 확인한다.
- 새 페이지를 추가하면 SUMMARY.md의 등록 필요 여부를 확인한다.
- git diff --check로 공백 오류를 확인한다.
- 실행하지 않은 명령이나 테스트를 성공했다고 쓰지 않는다.

## 결과 보고

- 변경한 파일, 주요 변경점, 검증 결과를 간단히 설명한다.
```

이 예시는 저장소 운영 규칙을 제안한 것이다. 이 안내 문서 안의 코드 블록을 작성했다고 실제 `AGENTS.md`가 생성되거나
자동 적용되지는 않는다.

### 개인 지침과 하위 폴더 지침

| 위치                       | 용도                                    |
| -------------------------- | --------------------------------------- |
| `~/.codex/AGENTS.md`       | 여러 프로젝트에서 사용할 개인 기본 지침 |
| `<repo>/AGENTS.md`         | 저장소 공통 지침                        |
| `<repo>/backend/AGENTS.md` | backend 작업에 맞춘 세부 지침           |

Codex CLI는 전역 지침 다음에 저장소 루트부터 현재 작업 디렉터리까지의 지침을 합친다. 가까운 디렉터리의 지침이 충돌하는
상위 내용을 구체화한다. 같은 디렉터리에서는 `AGENTS.override.md`가 `AGENTS.md`보다 먼저 선택되며, 둘을 모두
합치는 방식은 아니다.

루트에서 시작했다고 모든 하위 폴더 지침이 시작 시 자동 수집되는 것은 아니다. 하위 폴더 규칙을 확인하려면 해당 디렉터리에서
새 세션을 시작해 적용 출처를 확인한다. 기본 합산 크기 제한은 32 KiB이므로 긴 매뉴얼을 전부 넣지 않는다.

- [공식 탐색 순서와 제한](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## Step 3. 반복 작업은 SKILL.md로 분리하기

처음 만드는 저장소용 스킬은 다음 구조로 둔다.

```shell
dev-note/
└── .agents/
    └── skills/
        └── write-dev-guide/
            └── SKILL.md
```

- 여러 저장소에서 개인적으로 쓰려면 `~/.agents/skills/write-dev-guide/SKILL.md`에 둔다.
- 프로젝트용 스킬은 저장소에 함께 관리할 수 있다.

스킬에는 YAML 머리말의 `name`, `description`이 필요하다. `description`은 자동 선택의 기준이므로 무엇을 할 수
있는지뿐 아니라 **어떤 요청에 사용할지** 적는다.

필요한 경우 `references/`, `scripts/`, `assets/`를 같은 스킬 폴더에 추가한다.

- [공식 스킬 형식과 위치](https://learn.chatgpt.com/docs/build-skills)

다음은 개발 가이드 작성용 예시다.

```markdown
---
name: write-dev-guide
description: 개발 도구의 설치·설정·연동 방법을 처음 따라 하는 독자용 Markdown 가이드로 작성하거나 전면 개편할 때 사용한다.
단순 오탈자 수정에는 사용하지 않는다.
---

# 개발 가이드 작성

## 시작 전 확인

- 대상 문서의 기존 내용과 사용자의 수정 요청을 읽는다.
- 새로 시작하는 안내인지 기존 환경의 문제 해결인지 구분한다.
- 버전과 설정이 달라질 수 있는 내용은 공식 문서에서 확인한다.

## 작성 절차

- 목표와 완료 후 기대 결과를 먼저 설명한다.
- 필요한 계정, 도구, 권한을 적는다.
- 예제 프로젝트와 파일 이름을 하나로 통일한다.
- 필요한 파일을 만드는 단계부터 작성한다.
- 각 단계에 실행 방법과 확인할 결과를 함께 적는다.
- 마지막에 전체 동작을 검증하는 방법을 추가한다.
- 흔한 오류와 확인 순서를 정리한다.

## 완료 기준

- 앞에서 만들지 않은 파일을 뒤에서 있다고 가정하지 않는다.
- 복사할 명령의 자리표시자는 교체 방법을 설명한다.
- 코드 블록, 링크, 단계 사이의 연결을 확인한다.
- 확인한 공식 자료의 링크를 해당 설명에 첨부한다.
```

### 실제 요청 예시

Codex CLI나 IDE에서 스킬을 명시적으로 지정하려면 다음처럼 요청한다.

```shell
$write-dev-guide
Docker를 처음 설치하고 컨테이너를 실행하는 가이드를
03_docker/docker_setup.md에 작성해 줘.
```

직접 만들기 어렵다면 제공되는 생성기를 사용할 수 있다.

```shell
$skill-creator
개발 도구의 설치·연동 가이드를 작성하는 저장소용 스킬을 만들어 줘.
사용 조건, 작성 절차, 완료 기준을 포함하고 스크립트는 필요 없어.
```

명시적으로 부르지 않아도 요청이 설명과 맞으면 선택될 수 있다. 스킬이 안 보이면 파일 위치와 머리말을 확인하고 Codex를 재시작한다.
[공식 스킬 호출·생성 방법](https://learn.chatgpt.com/docs/build-skills)

## Step 4. 긴 참고 자료는 별도 문서에 두기

다음은 내용이 늘어났을 때 사용할 구조 예시다.

```shell
.agents/skills/write-dev-guide/
├── SKILL.md
├── references/
│   └── guide-style.md
└── assets/
    └── guide-template.md
```

`SKILL.md`에는 필요한 시점과 읽을 경로를 명시한다.

```markdown
## 참고 자료

- 문서의 구성 방식을 정할 때 references/guide-style.md를 읽는다.
- 새 문서의 뼈대가 필요하면 assets/guide-template.md를 참고한다.
```

참고 자료는 파일을 옆에 놓기만 하는 것보다 언제 읽어야 하는지 적는 편이 명확하다. 다른 프로젝트에도 배포할 스킬에는
개인 컴퓨터의 절대 경로를 넣지 않는다.

## Step 5. 실제로 적용되는지 확인하기

### 공통 지침 확인

- `AGENTS.md`를 저장한 뒤 프로젝트 디렉터리에서 새 Codex 세션을 시작한다.
- 다음처럼 요청한다.

```shell
현재 적용 중인 AGENTS.md 파일 경로와 핵심 규칙을 알려줘.
파일 수정은 하지 마.
```

### 스킬 확인

- CLI의 `/skills` 또는 `$` 선택 목록에서 스킬이 보이는지 확인한다.
- 스킬을 명시적으로 지정해 작은 문서 작업을 요청한다.
- 결과가 사용 조건과 완료 기준을 만족하는지 직접 확인한다.

확인용 요청 예시는 다음과 같다.

```shell
$write-dev-guide
빈 예제 프로젝트에서 시작한다고 가정하고 Git 기본 사용법 문서를 작성해 줘.
파일 생성부터 첫 commit을 확인하는 과정까지 포함해 줘.
```

이름이 목록에 보이는 것과 지침을 잘 수행하는 것은 별개다. 본문에 불필요한 숫자 목록이 생겼는지, 파일 생성 단계가 빠졌는지 등 실제 결과도 점검한다.

## 지침을 잘 작성하는 방법

아래는 지침을 구체적으로 다듬는 예시다.

| 모호한 지침          | 구체적인 지침                                                     |
| -------------------- | ----------------------------------------------------------------- |
| 문서를 잘 써라       | 각 단계에 실행 방법과 정상 결과를 함께 적는다.                    |
| 기존 스타일을 따라라 | 기존 문서의 제목 수준, 불릿, 코드 블록 형식을 유지한다.           |
| 모든 것을 검증해라   | 변경한 링크와 코드 블록을 확인하고 실행한 검사만 보고한다.        |
| 질문하지 마라        | 사소한 형식은 기존 문서에 맞추고, 필수 정보가 없을 때만 질문한다. |
| 항상 최신으로 해라   | 버전별로 달라지는 설치 옵션은 공식 문서에서 확인한다.             |

- 관찰 가능한 행동과 완료 기준을 적는다.
- 규칙의 적용 범위를 적는다. 문서 규칙을 모든 코드 작업에 적용하지 않는다.
- 같은 규칙을 여러 파일에 복제하지 않는다.
- 실패한 사례를 발견하면 해당 규칙을 보완한다.
- 매번 예외가 필요한 규칙은 공통 규칙으로 적절한지 다시 검토한다.

## 자주 헷갈리는 점

| 질문                                    | 설명                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------- |
| 이 `003_codex_docs.md`가 자동 지침인가? | 사용 방법을 설명하는 문서다. 기본 자동 탐색 파일인 `AGENTS.md`와 역할이 다르다.  |
| SKILL.md를 루트에 하나 두면 되는가?     | 스킬마다 폴더를 만들고 `.agents/skills/<name>/SKILL.md` 형태로 둔다.             |
| 공통 규칙을 스킬에만 적어도 되는가?     | 선택되지 않은 스킬은 본문을 읽지 않을 수 있으므로 공통 규칙은 AGENTS.md에 둔다.  |
| 스킬은 프로그램처럼 자동 실행되는가?    | 모델이 읽고 수행하는 절차다. 별도 스크립트가 있어도 실제 실행과 검증이 필요하다. |
| 지침이 무시되면 길게 추가하면 되는가?   | 먼저 탐색 위치, override, 충돌, 사용 조건을 확인한다.                            |

처음에는 짧은 프로젝트 `AGENTS.md` 하나로 시작하고, 반복되는 작업이 분명해지면 스킬을 추가하는 구성을 권한다.
