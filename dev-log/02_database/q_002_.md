# 실행 계획 분석 체크리스트

실행 계획을 볼 때마다 아래 순서로 점검하면 병목을 빠르게 찾을 수 있습니다.
출력 노드와 옵션은 DBMS에 따라 다르므로 PostgreSQL과 MySQL의 문법을 구분합니다.

- 1. 예상 행 수와 실제 행 수의 괴리가 큰가? → PostgreSQL은 통계 갱신을,
     MySQL은 `ANALYZE TABLE`을 검토합니다.
- 2. Table Scan이 발생하는가? → 인덱스 누락뿐 아니라 작은 결과 집합·낮은 선택도도
     원인일 수 있으므로 실제 비용을 확인합니다.
- 3. `loops`가 큰 노드가 있는가? → 반복 횟수와 노드별 실제 시간을 함께 봅니다.
- 4. Materialize나 CTE 물리화가 불필요한가? → 인라인 처리 가능 여부와 메모리 사용량을
     검토합니다.
- 5. 조인 결과에 실제로 사용되지 않는 테이블이 있는가? → 불필요한 조인을 제거합니다.
- 6. 전체 실행 시간과 버퍼 읽기 중 어느 노드가 가장 큰 비중을 차지하는가?
     → 해당 노드부터 개선합니다.

개선 후에는 동일한 데이터 분포와 파라미터로 다시 실행하고, 결과의 정확성이 유지되는지
확인합니다. 실행 계획의 cost 숫자는 절대 시간이 아니라 같은 환경에서 비교하기 위한
상대적인 비용입니다.
