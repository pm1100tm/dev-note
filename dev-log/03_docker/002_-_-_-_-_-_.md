# 다른 Compose 프로젝트의 컨테이너 연결

서로 다른 Compose 프로젝트는 기본적으로 서로 다른 네트워크를 만든다. 프로젝트 B가
프로젝트 A의 DB나 Redis에 접근해야 한다면, 두 프로젝트가 같은 사용자 정의 네트워크에
참여하도록 설정한다.

## 네트워크 이름 확인

```shell
docker network ls
docker network inspect shop-dev_shop-local-network
```

Compose는 보통 `<project>_<network>` 형식으로 네트워크 이름을 만든다. 실제 이름은
`docker network ls`로 확인하고 추측하지 않는다.

## 프로젝트 A: 공유 네트워크 생성

```yaml
services:
  db:
    image: postgres:16-alpine
    networks: [shop-local-network]

networks:
  shop-local-network:
    name: shop-shared-network
```

## 프로젝트 B: 외부 네트워크 사용

```yaml
services:
  data-app:
    networks: [shop-shared-network]

networks:
  shop-shared-network:
    external: true
```

프로젝트 A를 먼저 `docker compose up -d`로 실행해 외부 네트워크를 만든다. `external: true`인
네트워크는 Compose가 생성하거나 삭제하지 않는다.

## 연결 방식과 점검

```shell
docker compose exec data-app getent hosts db
docker compose exec data-app sh -c 'nc -zv db 5432'
```

- 같은 네트워크의 컨테이너는 `db:5432`처럼 서비스 이름과 컨테이너 포트로 연결한다.
- 호스트에 게시한 포트(`5433:5432`)는 컨테이너 간 통신에 사용하지 않는다.
- DB 포트를 외부에 공개하지 않아도 같은 Docker 네트워크에서는 통신할 수 있다.
- 운영에서 프로젝트 간 네트워크 공유는 의존성을 강하게 만든다. 접근 범위와 인증 정보를 분리한다.
