# Docker 이미지 경량화와 멀티 스테이지 빌드

멀티 스테이지 빌드는 하나의 Dockerfile에 여러 `FROM`을 두고, 빌드 도구가 있는 단계와
실행 단계의 이미지를 분리하는 방법이다. 최종 이미지는 실행에 필요한 산출물만 가진다.

## Spring Boot 예시

```dockerfile
FROM gradle:8.10-jdk21 AS builder
WORKDIR /workspace
COPY gradlew gradle/ build.gradle settings.gradle ./
RUN ./gradlew dependencies --no-daemon || true
COPY . .
RUN ./gradlew bootJar --no-daemon

FROM eclipse-temurin:21-jre-jammy
WORKDIR /app
COPY --from=builder /workspace/build/libs/*.jar app.jar
USER 10001
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

- `builder`에는 Gradle과 JDK가 있지만, 최종 단계에는 JRE와 JAR만 남는다.
- `COPY --from=builder`는 이전 단계의 파일만 선택해 복사한다.
- 빌드 단계의 컴파일러·캐시·테스트 도구는 최종 이미지에 포함되지 않는다.

## Python 예시

```dockerfile
FROM python:3.13-slim AS builder
WORKDIR /build
COPY requirements.txt .
RUN pip wheel --no-cache-dir --wheel-dir /wheels -r requirements.txt

FROM python:3.13-slim
WORKDIR /app
COPY --from=builder /wheels /wheels
RUN pip install --no-cache-dir /wheels/* && rm -rf /wheels
COPY . .
USER 10001
CMD ["python", "main.py"]
```

C 확장 패키지를 빌드할 때 필요한 컴파일러와 헤더를 최종 이미지에서 제외할 수 있어 효과가
크다. 다만 런타임 공유 라이브러리가 필요하면 최종 단계에 별도로 설치해야 한다.

## 함께 적용할 원칙

- `.dockerignore`로 `.git`, 로컬 의존성, 테스트 산출물, 비밀 파일을 빌드 컨텍스트에서 제외한다.
- 의존성 정의 파일을 먼저 복사해 빌드 캐시를 살린다.
- 이미지는 크기만이 아니라 취약점, 시작 시간, 재현성까지 함께 확인한다.
- Alpine은 작지만 musl 호환성 문제가 있을 수 있으므로 무조건 선택하지 않는다.
