# macOS에서 PostgreSQL 설치하기

Homebrew를 사용하면 PostgreSQL을 쉽게 설치하고 서비스로 관리할 수 있습니다. 아래
예제는 PostgreSQL 14를 사용하지만, 프로젝트에서 지원하는 버전을 먼저 확인합니다.

## 설치

```shell
brew update
brew install postgresql@14
brew services start postgresql@14
```

설치된 패키지와 실행 파일의 위치는 다음 명령으로 확인합니다.

```shell
brew info postgresql@14
which psql
psql --version
```

## 접속

```shell
psql -h localhost -p 5432 -d postgres
```

기본 데이터베이스나 역할이 현재 macOS 사용자명으로 생성되지 않았다면 먼저
`template1`에 접속한 뒤 역할과 데이터베이스를 생성합니다.

```shell
psql -d template1
```

```sql
CREATE ROLE myuser LOGIN PASSWORD 'change-me';
CREATE DATABASE myuser OWNER myuser;
```

비밀번호는 문서나 셸 히스토리에 평문으로 남기지 않습니다. 로컬 개발에서도 실제
서비스 비밀번호를 재사용하지 않는 편이 안전합니다.

## 서비스 관리

```shell
brew services start postgresql@14
brew services stop postgresql@14
brew services restart postgresql@14
brew services list
```

서비스 대신 직접 실행할 때는 Homebrew가 안내한 데이터 디렉터리를 사용합니다.

```shell
/opt/homebrew/opt/postgresql@14/bin/postgres \
  -D /opt/homebrew/var/postgresql@14
```

## 접속 오류 확인

서버가 실행 중인지 확인합니다.

```shell
pg_isready -h localhost -p 5432
```

`No such file or directory`가 나오면 서비스가 중지되었거나 포트·소켓 경로가 다른
것일 수 있습니다. `brew services restart postgresql@14` 후 다시 확인합니다.

`database "사용자명" does not exist`가 나오면 접속 데이터베이스를 명시하거나 해당
데이터베이스를 생성합니다.

```shell
psql -d postgres
createdb myuser
psql -d myuser
```

## 삭제 시 주의

패키지 삭제와 데이터 디렉터리 삭제는 별개의 작업입니다. 데이터가 필요하다면 먼저
`pg_dump`로 백업하고, 확인 후 서비스와 패키지를 삭제합니다.

```shell
brew services stop postgresql@14
brew uninstall postgresql@14
```

`/opt/homebrew/var/postgresql@14`를 삭제하면 데이터베이스 클러스터가 영구적으로
삭제될 수 있으므로, 이 명령은 복구가 필요 없다는 것을 확인한 경우에만 실행합니다.
