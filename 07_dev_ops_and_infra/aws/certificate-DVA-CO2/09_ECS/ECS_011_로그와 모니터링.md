# 로그와 모니터링

[전체 목차](<./ECS_001_컨테이너와 ECS 기본 개념.md>)

## 학습 목표

- CloudWatch Logs, 지표, ECS events의 역할을 구분한다.
- Task 시작 실패와 런타임 장애의 조사 순서를 익힌다.
- Container Insights와 EventBridge의 활용 시점을 안다.

## 관측해야 할 세 영역

| 영역 | 확인 대상 | 대표 도구 |
| --- | --- | --- |
| 로그 | 애플리케이션 출력과 오류 | CloudWatch Logs |
| 지표 | CPU, 메모리, 요청 수, Task 수 | CloudWatch Metrics, Container Insights |
| 이벤트/상태 | 배치 실패, Task 교체, 배포 진행 | ECS Service Events, EventBridge |

하나만 보면 원인을 놓칠 수 있다. 예를 들어 CPU 지표가 정상이어도 ALB health check path가 틀리면 Task가 계속 교체된다.

## CloudWatch Logs

Task Definition의 `logConfiguration`에 `awslogs` 드라이버를 설정하면 컨테이너 `stdout`과 `stderr`를 Log Group과 Stream으로 전송한다.

실무 권장 사항:

- 컨테이너는 로컬 파일보다 표준 출력으로 로그를 기록한다.
- JSON 구조화 로그와 request/correlation ID를 사용한다.
- 환경과 서비스별 Log Group naming을 정한다.
- 보존 기간을 명시해 비용과 규정을 관리한다.
- 민감 정보, 토큰, 비밀번호를 로그에 남기지 않는다.

로그가 전혀 생기지 않으면 애플리케이션보다 먼저 Execution Role의 로그 권한, Log Group 설정, 네트워크 경로와 로그 드라이버 옵션을 확인한다.

## ECS Service Events와 stopped reason

Service Events는 Task 배치 실패, Load Balancer health 실패, 안정 상태 도달 여부 등 Scheduler의 판단을 보여준다. 중지된 Task의 `stopCode`, `stoppedReason`, 각 컨테이너의 `reason`과 `exitCode`는 시작 실패와 프로세스 종료 원인을 찾는 핵심 단서다.

```text
Task가 RUNNING에 도달하지 못함
  -> stopped reason
  -> image pull / secret / resource / network 확인

RUNNING 후 종료
  -> container exitCode와 app logs
  -> OOM / exception / signal 확인
```

중지된 Task 정보는 영구 보존되지 않으므로 EventBridge 규칙과 Lambda를 이용해 세부 정보를 저장하거나 알림을 보낼 수 있다.

## Container Insights

Container Insights는 Cluster, Service, Task, 컨테이너 수준의 집계 지표와 진단 정보를 제공한다. 기본 ECS 지표보다 세부적인 운영 가시성이 필요할 때 유용하지만 추가 비용을 고려한다.

## Alarm과 알림

다음 항목은 운영 Alarm 후보이다.

- Service running Task가 desired count보다 적음
- ALB healthy host 감소 또는 5xx 증가
- CPU/메모리 지속 과부하
- 배포 실패
- 애플리케이션 오류율과 지연 시간 증가
- SQS backlog 증가

EventBridge는 ECS Task 상태 변경 이벤트를 받아 Lambda, SNS 등으로 전달할 수 있다. 단순 로그 검색보다 장애 발생 즉시 자동 대응할 때 적합하다.

## 실무 장애 조사 순서

1. 영향 범위와 최근 배포 여부를 확인한다.
2. ECS deployment와 Service Events를 확인한다.
3. stopped reason과 container exit code를 본다.
4. CloudWatch Logs를 같은 시간대로 조회한다.
5. ALB, CloudWatch 지표와 dependency 상태를 비교한다.
6. 원인 해결 후 Alarm과 runbook을 보완한다.

## 시험 포인트

- 표준 출력 로그 수집: `awslogs` + CloudWatch Logs
- 로그 전송 권한: Task Execution Role
- 세부 컨테이너 지표: Container Insights
- 중지 Task 자동 알림: EventBridge Task State Change event
- Task가 왜 교체되는지 확인: Service Events와 stopped reason

## 연습문제

**문제.** 보안팀은 모든 ECS Task 중지 이벤트를 즉시 감지하고 실패 세부 정보를 저장하려 한다. 애플리케이션 코드를 바꾸지 않는 구성은?

**정답:** EventBridge에서 ECS Task State Change 규칙을 만들고 Lambda 또는 적절한 대상을 호출한다.
