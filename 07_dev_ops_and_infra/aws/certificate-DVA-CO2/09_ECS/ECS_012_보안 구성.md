# 보안 구성

[전체 목차](<./ECS_001_컨테이너와 ECS 기본 개념.md>)

## 학습 목표

- ECS 보안을 이미지, IAM, 네트워크, secret, 런타임 계층으로 나눈다.
- Secrets Manager와 Parameter Store의 활용을 이해한다.
- 최소 권한과 private networking을 적용한다.

## 계층별 보안

```text
Source and CI
  -> Image and ECR
     -> IAM
        -> VPC network
           -> Task runtime
              -> Logs and audit
```

한 계층의 보안 기능으로 다른 계층의 위험이 모두 해결되지는 않는다. private subnet에 있어도 Task Role이 과도하면 데이터가 노출될 수 있다.

## Secret 관리

민감 정보는 이미지, 소스 코드, Task Definition의 일반 환경 변수에 평문으로 저장하지 않는다.

### Secrets Manager

- 데이터베이스 비밀번호, API token 등 secret 저장
- 자동 rotation 워크플로 지원
- JSON secret의 특정 key 참조 가능

### SSM Parameter Store

- 설정과 secret 값을 계층형 이름으로 관리
- `SecureString`은 KMS 암호화 사용
- 단순한 구성 관리에 적합

Task Definition의 `secrets`로 값을 주입하면 컨테이너 시작 시 환경 변수로 전달된다. secret이 변경되어도 실행 중인 컨테이너 값은 자동 갱신되지 않으므로 새 Task를 배포해야 한다. 런타임에 최신 값이 꼭 필요하면 애플리케이션이 SDK로 조회하고 Task Role에 권한을 준다.

환경 변수로 주입된 secret은 컨테이너 내부 프로세스와 디버깅 도구에 노출될 가능성이 있으므로 접근 권한과 로그 출력을 제한한다.

## IAM 최소 권한

- 서비스별 Task Role 분리
- 리소스 ARN과 작업을 최소화
- Execution Role에 앱 업무 권한을 넣지 않음
- 배포 Role의 `iam:PassRole` 대상 제한
- 교차 계정 Repository/Resource Policy 검토
- KMS Key policy까지 함께 확인

## 네트워크 보호

- 외부 요청은 ALB에서 받고 Task는 private subnet에 배치
- Task SG는 ALB SG 또는 필요한 호출자 SG만 소스로 허용
- 외부 통신을 NAT, Endpoint, Firewall 정책으로 통제
- 가능한 경우 TLS를 사용하고 인증서는 ACM에서 관리
- 운영 Task에 public IP를 관성적으로 부여하지 않음

## 이미지 공급망

- 최소 base image와 고정 버전 사용
- ECR image scanning 활성화 및 결과 처리
- tag immutability 또는 digest 배포
- 불필요한 패키지와 build 도구 제거
- CI에서 secret을 이미지 layer에 복사하지 않음
- 서명과 provenance 요구가 있으면 공급망 검증 절차 추가

## 런타임 원칙

- 컨테이너를 root가 아닌 사용자로 실행
- 읽기 전용 root filesystem 적용 가능성 검토
- 불필요한 Linux capability 제거
- 임시 데이터와 영구 데이터를 분리
- ECS Exec 권한과 감사 로그를 제한적으로 운영

EC2 Launch Type에서는 같은 인스턴스의 컨테이너가 호스트 커널을 공유한다. 강한 Task 수준 격리가 중요하면 Fargate를 검토한다.

## 실무 Secret 교체 절차

1. Secrets Manager에서 새 값을 생성하거나 rotation한다.
2. 애플리케이션이 새 값과 호환되는지 확인한다.
3. ECS Service에 새 배포를 강제해 Task를 교체한다.
4. 오류율과 인증 실패를 모니터링한다.
5. 이전 자격 증명을 폐기한다.

## 시험 포인트

- DB 암호의 안전한 저장: Secrets Manager 또는 Parameter Store `SecureString`
- Task 시작 시 secret 조회 권한: Task Execution Role
- 앱이 런타임에 secret API 조회: Task Role
- 새 secret을 기존 Task에 반영: 새 Task 배포
- ALB만 Task에 접근: Task SG 소스를 ALB SG로 지정

## 연습문제

**문제.** Secrets Manager의 비밀번호를 회전했지만 실행 중인 ECS 컨테이너는 이전 환경 변수 값을 계속 사용한다. 가장 적절한 조치는?

**정답:** Service의 새 배포를 시작해 Task를 교체한다. 시작 시 주입된 환경 변수는 자동으로 갱신되지 않는다.

## 확인 문제

- [ ] 두 secret 저장 서비스의 공통점과 차이를 안다.
- [ ] secret 참조 방식에 따라 필요한 Role을 구분할 수 있다.
- [ ] 이미지 공급망 보호 방법을 세 가지 이상 말할 수 있다.
