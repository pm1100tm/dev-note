# 컨테이너와 ECS 기본 개념

DVA-C02 관점에서 ECS를 처음 공부할 때 핵심은 "컨테이너 앱을 AWS에서 어떻게 실행하고 유지하는가"이다.

깊은 Docker 내부 구조보다, 다음 흐름을 먼저 잡는 것이 중요하다.

```text
이미지
→ 실행 정의
→ 실행 단위
→ 서비스 유지
```

## 1. 컨테이너란?

컨테이너는 애플리케이션 실행에 필요한 코드, 런타임, 라이브러리, 설정을 하나로 묶은 실행 단위이다.

예를 들어 Spring Boot 앱을 컨테이너로 만들면 다음이 함께 패키징된다.

```text
Spring Boot JAR
+ Java Runtime
+ OS-level dependencies
+ 실행 명령
+ 환경 설정
```

컨테이너의 장점은 환경 차이를 줄이는 것이다.

```text
개발자 로컬에서 실행됨
→ 테스트 서버에서도 동일하게 실행 가능
→ 운영 서버에서도 동일하게 실행 가능
```

## 2. Docker Image와 Container

| 개념         | 의미                            |
| ------------ | ------------------------------- |
| Docker Image | 실행 가능한 애플리케이션 템플릿 |
| Container    | 이미지를 실제로 실행한 인스턴스 |

비유하면 다음과 같다.

```text
Docker Image = 클래스
Container = 객체
```

또는 다음처럼 볼 수 있다.

```text
Docker Image = 실행 파일
Container = 실행 중인 프로세스
```

## 3. Amazon ECS란?

Amazon ECS, 즉 Elastic Container Service는 AWS의 컨테이너 오케스트레이션 서비스이다.

쉽게 말하면 ECS는 다음 일을 해준다.

```text
컨테이너 실행
컨테이너 개수 유지
컨테이너 재시작
배포 관리
로드밸런서 연결
로그 수집 연동
IAM 권한 연결
Auto Scaling 연동
```

공식 설명 기준으로 ECS는 컨테이너를 실행, 중지, 관리하는 확장 가능한 컨테이너 관리 서비스이다.

참고: [Amazon ECS Getting Started](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/getting-started-fargate.html)

## 4. ECS 전체 흐름

ECS의 큰 흐름은 이렇게 보면 된다.

```text
Dockerfile 작성
→ Docker Image build
→ ECR에 Image push
→ ECS Task Definition 작성
→ ECS Service 생성
→ ECS가 Task 실행
→ ALB, CloudWatch, IAM 등과 연동
```

실제 AWS 구성으로 보면 다음과 같다.

```text
Developer
  ↓
Docker Image
  ↓
Amazon ECR
  ↓
ECS Task Definition
  ↓
ECS Service
  ↓
ECS Task
  ↓
Fargate or EC2
```

## 5. ECS 주요 구성요소

| 구성요소             | 의미                                                  |
| -------------------- | ----------------------------------------------------- |
| Cluster              | ECS 리소스를 묶는 논리적 공간                         |
| Task Definition      | 컨테이너 실행 설계도                                  |
| Task                 | Task Definition으로 실행된 실제 컨테이너 묶음         |
| Service              | Task 개수를 유지하고 배포를 관리하는 단위             |
| Container Definition | Task 안에서 실행할 개별 컨테이너 설정                 |
| Launch Type          | 컨테이너를 Fargate에서 실행할지 EC2에서 실행할지 결정 |

## 6. Cluster

Cluster는 ECS에서 Task와 Service가 실행되는 논리적 그룹이다.

중요한 점은 Cluster 자체가 서버는 아니라는 것이다. Cluster는 실행 환경을 묶는 관리 단위에 가깝다.

```text
ECS Cluster
  ├─ Service A
  │   ├─ Task 1
  │   └─ Task 2
  └─ Service B
      └─ Task 1
```

## 7. Task Definition

Task Definition은 ECS에서 가장 중요한 개념이다.

컨테이너를 어떻게 실행할지 정의하는 JSON 설계도이다.

포함되는 주요 설정은 다음과 같다.

```text
어떤 Docker Image를 사용할지
CPU / Memory를 얼마나 줄지
어떤 포트를 열지
환경변수는 무엇인지
로그를 어디로 보낼지
IAM Role은 무엇을 쓸지
Secrets Manager 값을 주입할지
```

공식 문서에서도 Task Definition을 애플리케이션의 blueprint, 즉 설계도라고 설명한다.

참고: [Amazon ECS task definitions](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_definitions.html)

## 8. Task

Task는 Task Definition을 기반으로 실제 실행된 단위이다.

```text
Task Definition = 설계도
Task = 설계도로 실행된 실제 컨테이너
```

하나의 Task 안에는 하나 이상의 컨테이너가 들어갈 수 있다.

예:

```text
Task
  ├─ app container
  └─ sidecar container
```

DVA-C02에서는 보통 단일 app container 기준으로 많이 나온다.

## 9. Service

Service는 Task를 안정적으로 유지하는 역할을 한다.

예를 들어 Service에 desired count를 2로 설정하면 ECS는 항상 Task 2개가 실행되도록 유지한다.

```text
Desired count = 2

Task 1 running
Task 2 running
```

만약 Task 하나가 죽으면 다음처럼 ECS Service가 새 Task를 실행한다.

```text
Task 1 stopped
Task 2 running

ECS Service가 새 Task 실행

Task 3 running
Task 2 running
```

즉, Service는 운영 환경에서 필수에 가깝다.

## 10. Fargate와 EC2 Launch Type

ECS는 컨테이너를 어디에서 실행할지 선택할 수 있다.

| 방식            | 설명                              |
| --------------- | --------------------------------- |
| Fargate         | 서버 관리 없이 컨테이너 실행      |
| EC2 Launch Type | 사용자가 EC2 인스턴스를 직접 관리 |

DVA-C02에서는 대부분 Fargate 중심으로 이해하면 된다.

Fargate의 핵심은 다음과 같다.

```text
EC2 서버 관리 안 함
Task 단위로 CPU/Memory 지정
awsvpc 네트워크 모드 사용
Task마다 ENI가 붙음
```

## 11. ECR과 ECS 관계

ECR은 Docker Image 저장소이다.

ECS는 ECR에 저장된 이미지를 가져와서 컨테이너로 실행한다.

```text
ECR = 이미지 저장소
ECS = 이미지를 실행하는 서비스
```

예:

```text
1. Spring Boot 앱 Docker Image 생성
2. ECR에 push
3. ECS Task Definition에서 image URI 지정
4. ECS가 해당 이미지를 pull
5. Task 실행
```

## 12. 반드시 암기할 것

| 질문               | 답                               |
| ------------------ | -------------------------------- |
| ECS는 무엇인가?    | 컨테이너 실행/관리 서비스        |
| ECR은 무엇인가?    | Docker Image 저장소              |
| Task Definition은? | 컨테이너 실행 설계도             |
| Task는?            | 실제 실행된 컨테이너 단위        |
| Service는?         | Task 개수를 유지하고 배포를 관리 |
| Cluster는?         | ECS 리소스를 묶는 논리적 공간    |
| Fargate는?         | 서버리스 컨테이너 실행 환경      |

## 13. 시험 포인트

DVA-C02에서는 이런 식으로 나올 가능성이 높다.

```text
컨테이너 이미지를 저장해야 한다
→ Amazon ECR

컨테이너 실행 설정을 정의해야 한다
→ Task Definition

컨테이너를 항상 3개 유지해야 한다
→ ECS Service desired count

서버 관리 없이 컨테이너를 실행하고 싶다
→ ECS on Fargate

컨테이너 앱이 S3에 접근해야 한다
→ Task Role

ECS가 ECR에서 이미지를 pull해야 한다
→ Task Execution Role
```

## 14. 한 문장 요약

순서 1의 목표는 아래 한 문장을 자연스럽게 설명할 수 있는 상태가 되는 것이다.

```text
ECS는 ECR에 저장된 컨테이너 이미지를 Task Definition에 따라 Task로 실행하고,
Service를 통해 원하는 개수만큼 안정적으로 유지하는 AWS 컨테이너 관리 서비스다.
```
