# ECS Launch Type: EC2와 Fargate 선택 기준

> 확인일: 2026-09-29

- ECS의 Launch Type은 태스크를 실행할 컴퓨팅 환경을 고르는 기준입니다.
- 앞선 문서에서 살펴본 Cluster, Task Definition, Service는 동일하게
  사용하며, 여기서는 태스크 실행 서버를 누가 관리할지만 비교합니다.

## EC2 Launch Type

EC2 Launch Type은 사용자가 준비한 EC2 인스턴스에 태스크를 배치하는 방식입니다.
각 EC2에는 ECS Agent가 실행되어 Cluster에 등록되어야 합니다. ECS는 태스크를 시작하고 중지하지만,
EC2의 생성·패치·용량 확장·장애 대응은 사용자의 책임입니다.

- 팀이 EC2, AMI, 패치, ECS Agent를 관리합니다.
- 태스크 수와 EC2 용량을 모두 고려합니다.
- 인스턴스 타입, GPU, 로컬 디스크, 커널을 제어합니다.
- 여러 태스크를 채워 넣으면 단가를 낮추기 쉽습니다.
- 장기 실행, 높은 자원 밀도, 특수 하드웨어가 필요한 경우입니다.

### 장점

- GPU, 특정 인스턴스 타입, 사용자 지정 AMI가 필요할 때 선택할 수 있습니다.
- 여러 태스크를 한 EC2에 밀집 배치해 자원 사용률을 높일 수 있습니다.
- 호스트 수준 모니터링 Agent, 로컬 디스크, privileged 컨테이너처럼 Fargate에서 제한되는 기능을
  사용할 수 있습니다.

따라서,

- 태스크가 장시간 안정적으로 실행되고, 인스턴스 자원을 충분히 채울 수 있습니다.
- GPU, 커널 설정, 특수 네트워크처럼 호스트 제어가 필요합니다.
- EC2 패치와 Auto Scaling Group 운영을 맡을 수 있습니다.

## Fargate Launch Type

Fargate는 태스크를 실행하는 서버리스 컴퓨팅 엔진입니다.
사용자는 Task Definition에 CPU와 메모리를 지정하고 태스크 수를 조절합니다.
EC2 인스턴스, 운영체제, ECS Agent, 기반 서버 용량은 AWS가 관리합니다.

- AWS가 태스크 실행 서버를 관리합니다.
- 주로 태스크 수만 조절합니다.
- 호스트에는 접근하지 못하며 일부 설정이 제한됩니다.
- 태스크가 요청한 vCPU·메모리 기준으로 과금됩니다.
- 변동형 서비스, 배치 작업, 적은 운영 인력에 적합합니다.

### 장점

- 서버 프로비저닝, 패치, ECS Agent 관리를 하지 않아도 됩니다.
- 태스크 단위로 필요한 CPU와 메모리를 선언하므로 작은 서비스와 일시적인 배치 작업을 빠르게 시작할 수 있습니다.
- 트래픽 변화에 따라 태스크 수를 늘릴 때 EC2 용량을 별도로 계산하고 확보할 필요가 없습니다.

따라서,

- 서버 운영보다 애플리케이션 개발과 배포에 집중해야 할 수 있습니다.
- 트래픽 또는 배치 실행 시간이 불규칙합니다.
- GPU, privileged 컨테이너, 호스트 수준 Agent가 필요하지 않습니다.

## 비용 판단

### EC2

EC2 비용은 인스턴스가 켜져 있는 시간과 유형을 기준으로 발생합니다.
태스크가 적어도 EC2 요금은 계속 발생하므로 유휴 용량이 많으면 낭비가 됩니다. 반대로 많은 장기 실행
태스크를 같은 인스턴스에 효율적으로 배치하면 태스크당 비용을 낮출 수 있습니다.

예측 가능한 상시 사용량에는 Savings Plans나 Reserved Instances를 검토할 수 있습니다.
중단되어도 되는 워커에는 Spot Instance를 사용할 수 있지만, EC2 회수에 대비한 재시도와 정상 종료 설계가
필요합니다.

### Fargate

Fargate는 태스크가 요청한 vCPU, 메모리, 추가 임시 스토리지와 실행 시간을 기준으로 과금됩니다.
초 단위 과금이므로 짧게 실행하는 배치 작업이나 수요가 변하는 서비스에서 유휴 서버 비용을 줄이기 좋습니다.

반대로 항상 많은 태스크를 실행한다면, 태스크별로 예약한 자원을 계속 지불하므로 EC2에 밀집 배치하는 방식보다
비쌀 수 있습니다.

비용 비교에는 컴퓨팅 요금뿐 아니라 EC2 운영 인력, 유휴 용량, NAT Gateway·로그·데이터 전송 같은 주변 비용도 포함해야 합니다.

중단을 허용할 수 있는 작업은 `FARGATE_SPOT` Capacity Provider를
사용해 비용을 줄일 수 있습니다.

다만 Fargate Spot 태스크는 중단될 수 있으므로, 웹 API의 유일한 복제본으로 사용하면 안 됩니다.

## 선택 기준

| 요구사항                                          | 우선 검토                  |
| ------------------------------------------------- | -------------------------- |
| 서버를 관리하지 않고 빠르게 배포하고 싶습니다.    | Fargate                    |
| 트래픽이 불규칙하거나 단발성 배치 작업입니다.     | Fargate                    |
| GPU, 특수 인스턴스, 사용자 지정 AMI가 필요합니다. | EC2                        |
| 많은 장기 실행 태스크를 높은 밀도로 운영합니다.   | EC2                        |
| 중단 가능한 워커 비용을 줄이고 싶습니다.          | Fargate Spot 또는 EC2 Spot |

"Fargate가 항상 비싸다" 또는 "EC2가 항상 저렴하다"고 단정하면 안됩니다.
실제 태스크의 CPU·메모리 예약량, 실행 시간, 평균 사용률, 운영 인력과 중단 허용 여부를 함께 계산해 결정합니다.

현재 AWS는 Launch Type을 직접 지정하는 방식보다 Capacity Provider로 실행 용량을 선택하는 방식을 권장합니다.
