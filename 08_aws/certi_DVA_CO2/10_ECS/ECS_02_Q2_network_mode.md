# Network Mode

## `awsvpc`, `bridge`, `host`, `none`은 무엇이 다른가요?

Network Mode는 태스크 안의 컨테이너가 네트워크에 연결되는 방식을 정합니다.

Fargate 태스크는 `awsvpc`만 사용할 수 있습니다.
반면 EC2의 Linux 태스크는 필요에 따라 `awsvpc`, `bridge`, `host`, `none` 중 하나를 선택할 수 있습니다.

| Network Mode | 네트워크 방식                                     | 태스크별 ENI | 주로 고려할 상황                                    |
| ------------ | ------------------------------------------------- | ------------ | --------------------------------------------------- |
| `awsvpc`     | 태스크에 VPC 네트워크를 직접 부여합니다.          | 예           | Fargate, 태스크별 보안 그룹, VPC 자원 연결          |
| `bridge`     | EC2 호스트의 Docker 가상 네트워크를 사용합니다.   | 아니요       | EC2 Linux에서 동적 포트 매핑이 필요한 경우          |
| `host`       | 컨테이너 포트를 EC2 호스트 ENI에 직접 연결합니다. | 아니요       | 포트 격리가 필요 없고 호스트 네트워크가 필요한 경우 |
| `none`       | 외부 네트워크를 연결하지 않습니다.                | 아니요       | 네트워크 통신이 전혀 필요 없는 제한된 작업          |

### `awsvpc`

- ECS가 태스크마다 ENI를 만들고 VPC 서브넷의 사설 IP와 보안 그룹을 연결합니다.
- 태스크는 EC2 인스턴스처럼 VPC 안에서 보이며, 태스크별 보안 그룹과 VPC Flow Logs를 적용할 수 있습니다.
- 같은 태스크 안의 컨테이너는 하나의 네트워크 스택을 공유하므로 `localhost`로 서로 통신할 수 있습니다.

Fargate는 `awsvpc`가 필수입니다. EC2에서 `awsvpc`를 쓰면 태스크의 ENI 수가 인스턴스의 ENI 한도와
태스크 배치 가능 수에 영향을 줄 수 있으므로, 고밀도 배치에서는 인스턴스 타입과 ENI 한도를 함께
확인해야 합니다.

#### `bridge`

`bridge`는 EC2 Linux 호스트의 Docker bridge 네트워크를 사용합니다.
컨테이너는 호스트 내부의 가상 네트워크에 연결되며, 태스크마다 VPC ENI나 보안 그룹이 생기지 않습니다.
외부에서 접근하려면 EC2 호스트의 ENI와 포트를 통해 접근해야 합니다.

특히 동적 포트 매핑을 사용하면 ECS가 호스트의 사용 가능한 포트를 컨테이너 포트에 할당할 수 있습니다.
여러 태스크를 하나의 EC2에 밀집 배치하기 좋지만, 네트워크 보안 제어 단위가 태스크가 아니라
EC2 인스턴스라는 점을 이해해야 합니다.

#### `host`

`host`는 컨테이너 포트를 EC2 인스턴스의 네트워크 인터페이스에 직접 연결합니다.
Docker bridge를 거치지 않아 단순하지만, 같은 호스트에서 같은 포트를 여러 태스크가 함께 사용할 수 없습니다.
또한 동적 포트 매핑을 사용할 수 없으므로, 여러 복제본을 한 EC2에 실행해야 하는 일반적인 웹 서비스에는 제약이 큽니다.

#### `none`

`none`은 태스크에 외부 네트워크 연결을 제공하지 않습니다. 이미지 가져오기 같은 태스크 시작 과정의
연결과는 별개로, 실행된 컨테이너는 외부 서비스나 다른 호스트와 통신할 수 없습니다.
완전히 독립된 계산 작업처럼 네트워크가 필요 없는 경우에만 검토합니다.

### ENI는 무엇이며, 왜 태스크에 연결하나요?

- ENI(Elastic Network Interface)는 VPC 안의 가상 네트워크 카드입니다.
- 사설 IP 주소, 보안 그룹, MAC 주소 등의 네트워크 속성을 가집니다.
- EC2 인스턴스의 네트워크 카드와 비슷하게 생각할 수 있습니다.

`awsvpc` 모드에서는 ECS가 태스크마다 ENI를 생성하고, 지정한 서브넷과 보안 그룹을 연결합니다.
태스크가 중지되거나 Service가 축소되면 ECS가 그 ENI를 제거합니다.
사용자가 실행 중인 태스크의 ENI를 임의로 분리하거나 수정하면 안 됩니다.

태스크별 ENI가 필요한 이유는 다음과 같습니다.

- 태스크마다 고유한 사설 IP를 받아 ALB Target Group에 `ip` 대상 유형으로 직접 등록할 수 있습니다.
- 웹 API 태스크에는 ALB에서 오는 8080 포트만 허용하고, 워커 태스크는
  인바운드 연결을 모두 막는 식으로 보안 그룹을 분리할 수 있습니다.
- 태스크 단위의 VPC Flow Logs와 보안 규칙을 적용해 문제의 통신 경로를 더 세밀하게 확인할 수 있습니다.

따라서 **모든 ECS 태스크가 태스크별 ENI를 갖는 것은 아닙니다.**

Fargate 태스크와 `awsvpc` 모드의 EC2 태스크만 태스크별 ENI를 가집니다.

`bridge`, `host`, `none` 모드의 EC2 태스크는 호스트 EC2의 ENI를 공유하거나, 외부 네트워크를 사용하지 않습니다.
