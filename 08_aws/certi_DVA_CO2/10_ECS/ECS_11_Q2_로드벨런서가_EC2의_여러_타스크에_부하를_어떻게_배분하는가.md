# Q. 로드벨런서가 EC2의 여러 타스크에 부하를 어떻게 배분하는가

로드 밸런서는 “EC2 한 대”에 요청을 보내는 것이 아니라, ECS가 등록한 **각 태스크의 접속 주소**에 요청을 보냅니다.

예를 들어 EC2 한 대에 태스크가 3개 있어도, ALB의 Target Group에는 다음처럼 별도 대상으로 등록됩니다.

```
ALB Target Group

EC2-1:32768 → Task A
EC2-1:32769 → Task B
EC2-1:32770 → Task C

EC2-2:32768 → Task D
EC2-2:32769 → Task E
```

- ALB는 `EC2-1`이라는 서버 자체에 한 번만 보내는 것이 아닙니다.
- `EC2-1:32768`, `EC2-1:32769`처럼 **포트까지 포함한 태스크 엔드포인트**를
  서로 다른 Target으로 인식합니다.
- 그래서 같은 EC2 안의 Task A, B, C에도 각각 요청을 분산할 수 있습니다.

## ECS의 네트워크 모드에 따라 등록 방식이 달라집니다.

| 네트워크 모드 | ALB가 태스크를 구분하는 방식                                                                                               |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `awsvpc`      | 태스크마다 별도 ENI와 사설 IP를 가지므로 `태스크 IP:컨테이너 포트`로 등록합니다.                                           |
| `bridge`      | 같은 EC2 IP를 공유하지만 태스크마다 동적 Host Port를 받아 `EC2 IP:Host Port`로 등록합니다.                                 |
| `host`        | EC2의 포트를 컨테이너가 직접 씁니다. 같은 포트를 쓰는 동일 태스크 여러 개를 한 EC2에 둘 수 없어 밀집 배치에 제약이 큽니다. |

예를 들어 `bridge` 모드라면 태스크 정의에는 애플리케이션 포트만
`8080`으로 두고, Host Port는 ECS가 자동으로 할당하도록 설정합니다.

```
Task A: 컨테이너 8080 → EC2-1의 32768 포트
Task B: 컨테이너 8080 → EC2-1의 32769 포트
```

ALB는 두 Target을 별개로 헬스 체크하고, 정상인 태스크에 요청을
분산합니다. Task B만 비정상이면 `EC2-1` 전체를 제외하는 것이 아니라
Task B의 `EC2-1:32769`만 제외합니다.

실무에서는 ECS와 ALB를 연결할 때 주로 `awsvpc` 네트워크 모드를 씁니다.
이 경우 태스크마다 IP가 있으므로 구조가 더 명확합니다.

```
ALB
 ├─ 10.0.1.101:8080 → Task A, EC2-1 위에서 실행
 ├─ 10.0.1.102:8080 → Task B, EC2-1 위에서 실행
 └─ 10.0.2.101:8080 → Task C, EC2-2 위에서 실행
```

즉, 태스크를 여러 EC2에 분산하면 EC2 장애 영향 범위도 줄어들고,
같은 EC2에 여러 태스크를 두더라도 ALB는 각 태스크 단위로 요청과
헬스 체크를 처리할 수 있습니다.
