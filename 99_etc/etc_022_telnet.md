# telnet

윈도우에서 telnet 명령어가 인식되지 않을 수 있다. 기본적으로 텔넷 클라이언트 기능이 꺼저있기 때문이다.

## 해결 방법

- win + R
- optionalfeatures 입력, 또는 제어판 window 기능 켜기/끄기 이동
- 나타나는 Windows 기능 창에서 아래로 내려, telnet client 항목 체크
- 확인 > 잠시 기다리면 윈도우가 필요한 파일 설치
- cmd 새로 열고 telnet 명령어 실행

## telnet IP 의 의미, 그리고 mac 에서 이와 대응하는 명령어

'telnet [IP]'는 특정 IP 주소를 가진 서버의 특정 네트워크 포트가 열려 있는지, 그리고 연결이 가능한지
확인하는 명령어입니다.

과거에는 서버 원격 제어용으로 썼으나, 현재는 네트워크 연결 상태를 진단하는 용도로 주로 사용합니다.

Mac(맥OS)은 최신 버전에서 보안상의 이유로 telnet을 기본 제공하지 않으므로, 아래의 대응 명령어를
사용해야 합니다.

### Mac에서 사용하는 대응 명령어

맥에 기본 내장되어 있어 별도 설치가 필요 없고, telnet과 작동 방식이 가장 유사합니다.

```shell
$ nc -vz [IP주소] [포트번호]
# ex) nc -vz 192.168.1.1 80
# 연결 성공 시 succeeded, 실패 시 timeout 또는 refused가 뜹니다.
```

포트 확인이 아닌, 현재 Mac의 전반적인 네트워크 인터넷 속도와 품질을 진단하고 싶을 때 사용합니다.

```shell
$ networkQuality
```

### 만약 꼭 기존 'telnet'을 쓰고 싶다면?

설치 후 기존 방식대로 telnet [IP주소] [포트번호]를 사용합니다.

```shell
brew install telnet
```

## nslookup 과 telnet

`nslookup`과 `telnet`은 확인하는 대상이 다릅니다.

- `nslookup`: 도메인 이름이 어떤 IP로 해석되는지 확인한다. 즉, DNS 조회 도구다.
- `telnet`: 특정 IP 또는 도메인의 특정 포트에 실제로 접속 가능한지 확인한다. 즉, 포트 연결 확인 도구다.

예를 들어 `example.com` 서버에 접속이 안 될 때:

```shell
nslookup example.com
```

위 명령어가 실패하면 DNS 문제일 가능성이 큽니다.

```shell
telnet example.com 443
```

위 명령어가 실패하면 DNS는 되었더라도 방화벽, 포트 차단, 서버 미동작 등의 문제일 수 있습니다.

정리하면 `nslookup`은 "주소를 찾을 수 있는가", `telnet`은 "그 주소의 포트까지 연결되는가"를 확인합니다.

### 특정 IP와 포트 확인 순서

특정 IP 주소가 열려 있는지 보고, 그 다음 포트까지 확인하려면 보통 아래 순서로 봅니다.

1. IP 자체가 응답하는지 확인

```shell
ping [IP주소]
# ex) ping 192.168.1.10
```

2. 특정 포트가 열려 있는지 확인

```shell
telnet [IP주소] [포트번호]
# ex) telnet 192.168.1.10 80
```

Mac/Linux에서는 `telnet` 대신 `nc`를 쓰는 경우가 많습니다.

```shell
nc -vz [IP주소] [포트번호]
# ex) nc -vz 192.168.1.10 80
```

해석은 아래처럼 하면 됩니다.

- `ping` 실패: IP가 죽었거나 네트워크 경로 문제일 수 있다. 단, 방화벽이 ICMP만 막은 경우도 있다.
- `ping` 성공 + `telnet/nc` 실패: 서버는 보이지만 해당 포트가 닫혔거나 방화벽에 막혔을 수 있다.
- `ping` 성공 + `telnet/nc` 성공: 해당 IP의 해당 포트까지 연결 가능하다.

실무에서는 `ping`이 막혀 있는 서버도 많기 때문에, 포트 오픈 여부는 `telnet` 또는 `nc` 결과를 더 중요하게 봅니다.

#### Q. ping [IP] 만 하면 기본적으로 port 는 80이라고 보는가?

No ❎ > ping [IP]에는 포트 개념이 없습니다.

ping은 TCP/UDP 포트로 접속하는 명령이 아니라, ICMP라는 별도 프로토콜로 “이 IP가 네트워크상에서 응답하는가”만 확인합니다.

즉:

```
ping 192.168.1.10

이건 아래 의미가 아닙니다.

192.168.1.10:80 확인

정확한 의미는 이쪽입니다.

192.168.1.10 IP가 ICMP 요청에 응답하는지 확인
포트 80을 확인하려면 반드시 포트를 지정해야 합니다.

telnet 192.168.1.10 80

또는:

nc -vz 192.168.1.10 80

정리하면:

ping [IP] -> IP 응답 확인, 포트 없음
telnet [IP] [PORT] -> 특정 포트 연결 확인
nc -vz [IP] [PORT] -> 특정 포트 연결 확인
```
